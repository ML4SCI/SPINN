# 3D Trap Geometries

Full 3D ion-trap simulations using the same DEVSIM base-function + RF pseudopotential approach as the [2D simulations](../2D_Geometries/), extended to tetrahedral meshes.

Each subdirectory is a self-contained pipeline with four scripts that should be run in order:

```bash
python gmsh_script.py          # build the 3D mesh
python paul_trap_sim_DC.py     # solve DC base functions for each DC electrode
python paul_trap_sim_RF.py     # solve RF amplitude and compute gradient
python visualize_results.py    # combine into Psi, render with PyVista
```

## Geometries

### [Linear_blade_trap/](Linear_blade_trap/)

Four blade electrodes parallel to the trap axis (z), with two cylindrical endcap electrodes for axial confinement. Radial confinement comes from the RF quadrupole formed by the two blades on +/- x; axial confinement comes from the endcap DC bias. This is the workhorse geometry for ion-chain experiments.

- **RF electrodes:** `RF_East`, `RF_West` (driven 180° out of phase with the DC blades, or just at +RF with DC blades grounded as in this implementation)
- **DC electrodes:** `DC_North`, `DC_South`, `Endcap_Top`, `Endcap_Bot`
- **Trap center:** origin
- **Look for:** radial quadrupole pseudopotential in the z=0 slice; axial harmonic well along the z-axis from the endcaps.

### [Classical_3D_Paul_trap/](Classical_3D_Paul_trap/)

Wolfgang Paul's original 1953 design: a hyperboloidal ring electrode and two hyperboloidal endcap electrodes, all generated by revolving (r,z) hyperbolic profiles around the z-axis. The geometry uses the ideal Paul ratio r₀² = 2 z₀², where r₀ is the saddle-point radius and z₀ is the axial half-spacing.

- **RF electrode:** `Ring`
- **DC electrodes:** `Endcap_Top`, `Endcap_Bot`
- **Trap center:** origin (the saddle point)
- **Look for:** spherical-ish pseudopotential well at the origin; the cylindrical symmetry of the field; the characteristic hyperboloidal electrode profiles visible in the y=0 slice.

### [Surface_electrode_trap/](Surface_electrode_trap/)

A "5-wire" planar surface-electrode trap: three DC strips and two RF rails patterned on the chip plane (z=0). The ion floats in vacuum at z > 0, above the chip surface, with its height set by the geometry of the RF rails.

- **RF electrodes:** `RF_North`, `RF_South`
- **DC electrodes:** `DC_Center`, `DC_North`, `DC_South`
- **Trap center:** above the chip, at (0, 0, z_trap) where z_trap is on the order of the RF rail width
- **Look for:** pseudopotential minimum in the yz-slice at x=0, well above the chip surface; symmetry breaking when DC_North / DC_South are biased differently (transverse compensation).
- **Note:** the gaps between electrodes are modeled as grounded (a standard simplification — real gaps are floating insulator).

### [Stylus_trap/](Stylus_trap/)

A single central RF needle ("stylus") with a surrounding grounded washer and two DC compensation pads. Modeled on Maiwald et al. (2009). The ion is trapped in the open volume above the needle tip, giving near-4π optical access.

- **RF electrode:** `Stylus_RF`
- **DC electrodes:** `Ground_Ring`, `DC_Comp_E`, `DC_Comp_W`
- **Trap center:** above the stylus tip, at z ≈ a few hundred μm
- **Look for:** pseudopotential minimum directly above the tip; the strong RF field gradient near the tip (visualization caps values at the 90th percentile to keep colormaps useful).

## Geometry construction pattern

All four scripts use OpenCASCADE (Gmsh OCC) primitives and the same physical-group tagging recipe:

1. Build the world box and each electrode body as separate OCC volumes.
2. `gmsh.model.occ.fragment()` the world with the electrodes — this produces conformal shared interfaces between adjacent volumes.
3. Identify the **air** fragment as the world fragment that is not also an electrode fragment.
4. Tag physical groups:
   - One 3D group per electrode volume (so DEVSIM can register the region) plus one for `air`.
   - One 2D group per electrode-air interface (named `<Electrode>_contact`) — Dirichlet boundary condition surfaces.
   - One 2D group `world_boundary` for the outer faces of the air volume (top, sides, bottom).
5. Refine the mesh near electrodes and in the trap region using a Distance or Box mesh field.

The DEVSIM PDE setup in each `paul_trap_sim_*.py` is identical to the 2D code — the edge-based finite-volume discretization is dimension-agnostic. The only difference is that `vector_gradient` in 3D produces `Potential_gradx`, `Potential_grady`, `Potential_gradz` (rather than just gradx, grady in 2D), and `|∇Φ|²` in the pseudopotential formula uses all three components.

## Units and conventions

All geometry is in **centimeters** to match the 2D codebase. This keeps the permittivity constant `eps0 = 8.854e-14 F/cm` consistent, and the `1.0e4` factor in each `visualize_results.py` converts `(V/cm)² → (V/m)²` before applying the pseudopotential formula

```
ψ_RF = e² / (4 M Ω²) · |∇Φ_RF|²
```

with M = Ca-40 ion mass and Ω/2π in the 10–30 MHz range (varies by geometry — surface and stylus traps run higher).

## Caveats

These 3D pipelines were written following the 2D pattern but were not yet executed end-to-end. The DEVSIM PDE setup is identical to the verified 2D scripts, but the OCC geometry construction and physical-group tagging are new and may need adjustment after the first run — particularly:

- Mesh refinement parameters (`world_mesh`, `electrode_mesh`, `trap_center_mesh`) may need tuning if Gmsh produces too many tetrahedra or too few.
- The `assert len(air_candidates) == 1` check in each `gmsh_script.py` will fail if any electrode protrudes through the world boundary or if two electrodes overlap.
- PyVista 3D rendering loads the Tecplot output via the same `pv.get_reader(...).read()[4]` index used in the 2D code; if the DEVSIM output structure differs in 3D the index may need updating.
